# Task EP-02: Premium UI foundation and motion

Branch: `feat/ep-02-design`. Epic file: `docs/superpowers/plans/EP-02-design.md`. Design direction: `docs/product/PRODUCT_SPEC.md` ("Design system direction") and section 4 of `docs/superpowers/plans/2026-11-13-opengym-next-master.md`.

Allowed new dependency: `motion` (MIT), only if a concrete transition needs it, and only loaded lazily. If CSS transitions do the job, do not add it and say so.

## Objective

Make Home and the workout flow feel more polished without adding a single tap, without slowing set entry, and without growing the first-load bundle. Later epics (analytics, nutrition, activity) will build their screens from the primitives you add, so they must be small, accessible and documented.

## Deliverables

1. **Before state.** Run the app (api with a throwaway `DATA_DIR`, frontend dev server, a synthetic profile with a few workouts) and capture Home, an active workout, Stats and Settings at 320, 390 and 1280 px, dark and light. Save under `docs/superpowers/evidence/EP-02/before/`. Count taps and focus stops to log one set; that number may not go up.
2. **Design note.** `docs/superpowers/plans/EP-02-tasks.md`: the constrained token refresh you propose (surfaces, one accent, type scale, tabular numerals, spacing, radius, focus ring), mapped onto the **existing** CSS variables and themes. Extend existing tokens before adding new ones. Every existing theme, including seasonal ones, must still work.
3. **Primitives**, each with a Vitest component test covering role, name, keyboard and empty/error state: metric card, section/list row, skeleton, empty state, error state with retry. Put them where shared UI already lives (`frontend/src/components/`). Minimum 44 by 44 CSS px touch targets, visible focus, no colour-only status, contrast at WCAG 2.2 AA.
4. **Use them in one real screen** (a Home card is the natural place) with no behaviour change. Existing tests for that screen stay green untouched, or the change is explained line by line.
5. **Motion.** At most two targeted transitions (for example bottom-sheet spring and a small staggered entrance on a non-critical list). A `prefers-reduced-motion` branch that removes them. Nothing may delay a set tap, the rest timer or a save: prove it with an interaction test.
6. **After state and QA.** Same screenshots under `docs/superpowers/evidence/EP-02/after/`, plus one RTL locale and 200 percent text zoom. Console errors and failed requests listed. Bundle delta for the entry chunk and total against `docs/product/BASELINE_REPORT.md`; entry chunk growth must be near zero.
7. Locale keys for any new string in every pack.

# Accessibility checks (EP16-T02)

`frontend/e2e/a11y.e2e.mjs` runs axe-core (WCAG 2.0/2.1, levels A and AA) on `/home`, `/plan`, `/stats`, `/library` and `/addons` (with the 3D map open), as a guest with two workouts logged. A **serious** or **critical** violation fails the test, in CI (`e2e` job) and locally (`npm run test:e2e`).

## Fixed in this fork (2026-11-15)

| Rule | Where | Fix |
|---|---|---|
| color-contrast | `.addon-footnote` (3D map attribution, food footnote) | `--label-3` (32 % alpha) → `--label-2` |
| color-contrast | `.addon-roadmap-row small` (roadmap status) | `--label-2`, 10 → 11 px |
| non-text contrast (same token) | `.diary-remove` (the "×" control) | `--label-2` |

## Upstream baseline (not fixed here)

These violations are in upstream openGym's own screens, which this fork has not changed. The test skips exactly these rule ids on exactly these screens, so any **new** violation still fails. Report them upstream, and remove each entry from `UPSTREAM_BASELINE` once it's fixed there. The test logs when an entry no longer fires.

| Screen | Rule | Elements (first matches) | What it means |
|---|---|---|---|
| `/home` | label-content-name-mismatch (WCAG 2.5.3) | `button[aria-labelledby]`, `button[aria-haspopup="dialog"]` | The accessible name doesn't contain the visible text, so voice control ("click Start") misses it |
| `/plan` | label-content-name-mismatch | `div[data-day="1"]`, `div[data-day="2"]`, … | Same, on the week-day cells |
| `/stats` | label-content-name-mismatch | `.level-bar` | Same, on the muscle level bars |

## Not covered by automation

axe finds roughly a third to a half of WCAG issues. Still needed by hand, and on a real device (EP16-T03):
- screen reader passes (VoiceOver on iOS, TalkBack on Android) through Workout, Stats and Add-ons;
- 200 % text size;
- keyboard-only use of the 3D map list;
- `prefers-reduced-motion`.
